- In the Restricted Change Request values property add the fields that should not be selectable at all as part of the template. These have been preset out of the box to include obvious fields such as Active or closure information which should never be specified in the template.

- In the Read-only fields property add the fields that will be set to read only when a change is raised from a Standard Change Template. Typically this will match the fields specified as mandatory. This is where security is applied to the standard change process to prevent misuse. Fields that have been reviewed and approved as part of the template request process should not be altered once the change is raised. Any changes to the information in fields renders the change no longer valid as a Standard change. Typically this will include fields such as Implementation steps as these are authorized within the template request process and should never be changed. In the Fields to copy property ensure the fields entered match the fields added in the Mandatory Change Request values property. This will ensure all the data that is captured in the template is copied across to all new changes raised from it. Review the workflow associated with publishing requests to ensure the correct group is approving. Once the Standard Change Catalog has been configured ensure Story Configure Standard Change Workflow is also completed to provide the correct workflow for the changes to follow once raised from the template.
