## Slide 41

Default escalation policy

Escalation policies are defined on the shift

The default escalation policy is to rotate through the roster members in order, and then finally try the Catch-all user/group

Multiple escalation policies allow customers to create more than one custom escalation policy per shift, e.g., different escalation policies based on the priority of the incident, type of task record, etc.

### Speaker notes

Explain and discuss

When referring to Escalations and Escalation Policies, we are only talking about defining the people in the escalation chain/path.

There are no automated notifications along the escalation path unless there are Escalation Triggers defined (next)

For a Shift with only 1 Roster (just the Primary), the default escalation path is to rotate between all the members of that 1 roster. This means that people who are supposed to have a day off (not scheduled to be On-Call), may be contacted if the On-Call person is unresponsive.

For a Shift with multiple rosters (Primary, Secondary, etc), the default escalation path is to rotate through the On-Call person for each roster. On-Call person from the Primary roster, then On-Call person from the secondary roster, etc. People who are not On-Call for any roster are not contacted.

Default escalation polices can include an optional Catch-all. The options are:

Notify Group Manager (the Manager defined on the Group record)

Notify Individual (then specify a User in a reference field)

Notify Roster (then specify a Roster in a reference field – Usually the Primary roster)

None – there is no catch-all notification

Decisions to make

For all shifts that are using the default escalation

### Speaker notes

Explain and discuss

A custom Escalation Policy can be defined for each Shift. A Group with multiple Shifts can have multiple escalation policies – a different one for each Shift.

Any list of Users or groups can be defined in any order. Roster rotations are still possible. Scripted policies are NOT possible.

The screenshot shows the information required for each step in the custom escalation policy.

You can add as many steps as you like

You CANNOT add the Group that owns the Shift to the Groups field. That is, you cannot notify the entire Group in an escalation step.

Custom Escalation Policies are not reusable between shifts

Example: You can define a custom policy that still notifies the rostered On-Call people in order, but then has multiple fall-back contacts instead of the one “catch-all”. Like Group manager, then the manager’s manager.

Name: Display name

Escalation level: Escalation order

Number of reminders: How many email/SMS notification to send to the On-Call person

Time between reminders: How long to wait before sending the next notification to the same person

Time to next step: How long to wait between the last reminder for the current person and sending the first notification to the next person in the escalation chain. Setting this to 0 will mean that the secondary On-Call person will receive their first notification immediately after the primary On-Call person will receives their last notification.

Roster: Works with the next field to determine which people on this roster to notify
