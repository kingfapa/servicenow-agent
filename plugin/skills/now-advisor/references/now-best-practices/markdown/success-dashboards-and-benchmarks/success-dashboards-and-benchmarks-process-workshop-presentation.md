## Slide 23

How and what data is pulled from our ServiceNow instance?

We use anonymous, aggregated, usage data to calculate global benchmark KPIs from the ServiceNow cloud. Benchmark KPIs only use the usage count data (e.g. the total number of incidents) and no sensitive data (like CIs, names, IP addresses, etc) is used.  The aggregation occurs at a very high level: global, 10 Industry Categories, 5 Use Size buckets, and 3 geographic region buckets to calculate the monthly Benchmark value.  Each Industry Category/Size/Geo cohort bucket are big enough with a couple of hundred customers in each and we do not allow to use of more than one filter on the Benchmarks UI to maintain full anonymity.

How is data secured in transit from the customer instance to the central Benchmarks instance?

Data is sent using secure REST API calls. Participating instances upload the monthly KPI count information using a scheduled job in the first week of the month. After opting in, customers can pick and choose which KPI they want to participate in.

Where does the data get stored?

The Benchmarks KPI data is stored on a central Benchmarks instance in aggregated and anonymized form. ServiceNow Benchmarks instance is governed

Who can view the Benchmarks data once it has been downloaded to our instance?

When data is downloaded into a customer instance, the reports can only be viewed by individuals with Benchmarks roles (Viewer or Admin). Customers can request to determine who is allowed to view the Benchmarks reports within their company.

### Speaker notes

Self solved - percentage

How this is calculated

Self-solved percentage is calculated from the daily average number of times your users achieved resolution without intervention. Includes numbers from Self-solved using Virtual Agent, Self-solved using Knowledge and Automated resolutions (e.g. Incident auto-resolution via Virtual Agent).

Call deflection - percentage

How this is calculated

Call deflection is calculated from the number of times per day requestors performed the actions, Ticket submissions using Service Catalog, Ticket submissions using Virtual Agent, Self-solved using Virtual Agent and Self-solved using Knowledge without Tier 1 agent intervention.

% structured tickets completed

How this is calculated

Count percentage of tickets that were completed and were structured.

Productivity moments per user

How this is calculated

Instances where ServiceNow capabilities like NLU, LLM, Knowledge Article, Walk-up experience etc, helped either the agent or requestor in improving their productivity.

Incident summarization - Now Assist

## Slide 61

What code is intended to be altered by the customer?

Customers cannot modify primary indicators, as this is prescribed by ServiceNow (no write/edit access for the primary indicator table and the primary indicator registry table)

Customers can modify contributors to the primary indicator by

Adding their own indicators or removing the contributing indicators shipped by ServiceNow by using the contributing indicator registry table

How can customers be informed so they can avoid getting in this situation?

All features not intended to be modified by the customer have been protected such that they do not modify it

How can the customer modify the look and feel of the feature?

Customers can add or modify the contributors to a KPI and also add/remove/modify the contextual help cards for the KPIs. The cards can be modified in the Indicator Context Information Table, and the relationship of the cards to the indicators in the M2M Indicator Context Information table
