## Slide 31

Considerations for a new Service Catalog

All wording must be in the customer’s language - this means the end users of the services who are not likely to understand technical terminology

Do not require information to be entered if it can be automatically determined such as a line manager or contact information

Let the requester know when approval is needed and by whom

Make use of satisfaction surveys

Conduct focus sessions with infrequent customer requesters

### Speaker notes

Explain and discuss

Explain that for services being offered it is critical to remember the audience and use language they will understand

Explain that many commonly required pieces of information may already be known and stored in ServiceNow so it is important to look for opportunities to automatically detect those rather than insist the user has to manually enter them

Use surveys and focus sessions to run continuous improvement processes and ensure each service is performing at its best

Considerations

Due dates can be put on catalog tasks to help move the process along.

Creating an SLA for every task created for each item can lead to hundreds to configure and maintain.

Product Catalog

The product catalog is a set of information about individual models. Models are specific versions or various configurations of an asset. Asset managers use the product catalog as a centralized repository for model information

A detailed and well-maintained product catalog can coordinate with service catalog, asset, procurement, request, contract, and vendor information

Models published to the product catalog are automatically published to the Service Catalog. The service catalog includes information about goods (models) and services. If the model is available from multiple vendors, a model can be listed more than once. Models are included with the Asset Management application

Product catalog items are hardware and software that you can track and offer in the service catalog

The vendor catalog is a list of goods available from different vendors

Keep the following in mind when working with the product catalog:

A product catalog item can be linked to multiple vendor catalog items or to a single model

A model can only have one product catalog item

A vendor catalog item can only have a single product catalog item

## Slide 140

Catalog Builder Overview

Catalog Builder is a low-code builder tool that provides a guided, visual experience to create, publish, and maintain catalog items and re-usable catalog item templates.

Catalog Builder is designed to support the most common and simple use cases so that it can easily be used by business users without previous development experience. Complex functionality can be added to catalog items in the Now Platform by Catalog Administrators.

Catalog Administrators can delegate the creation of catalog items to business owners by creating catalog templates with pre-defined settings/restrictions. Business owners (Catalog Builder Editors) can then use those templates to create catalog items.

Within Catalog Builder you can create easy and simple steps to define the fulfillment process . The catalog item creator can give conditions for each step so that you can control when a step is run based on run time data. The condition builder has the current item’s stand-alone variables and variables in variable sets for selection and the step will be performed only when the condition evaluates to true.

See Creating Catalog Experiences with Catalog Builder
